<aside class="tldr">
面向协调代理商。采购方在看板上逐阶段跟踪每一张订单。它自己就能看到货物何时发出、何时送达，但看不到供应商那边发生了什么。这部分需要靠您来记录：在每张发给供应商的订单上，记录定金何时付清、样品何时核准、生产何时完成，以及您预计货物就绪的日期。每件事发生当天就记录。看板的采购方视角见 <a href="/docs/reading-the-po-journey-board">reading the PO journey board</a>（英文）。
</aside>

## 您的日期为什么重要

采购方通过您下达的每一张订单，都会在 <b>PO journey</b> 看板上显示为一行阶段：订单已创建、样品、定金、生产、质检、干净交接、已发货、运输中、已收货、已上线。每个阶段都有一个目标日期。阶段一旦超过目标日期，就会变红，并显示已经延误了多少天。

如果没有您记录的日期，看板在您这一端只能看到两件事：订单发给您的那天，以及货物离开的那天。中间发生的一切都是不可见的，不管延误发生在供应商那里、质检环节还是交接环节，看起来都一样。有了您的日期，看板就能准确显示订单走到了哪一步，供应商的延误在货物本该发运的几周之前就能被看到。

您在一张订单上记录了第一个日期之后，看板就会等着看后续的日期。如果某个阶段的目标日期已过，而您还没有记录，该阶段就会显示为延误，即使工作实际上已经完成。缺失的日期，看起来和真正的延误一模一样。

## 您需要记录的四个日期

| 日期 | 记录时机 | 说明 |
|---|---|---|
| <b>Deposit paid</b>（定金已付） | 您向供应商支付定金时。 | 请在同一页面一并记录 <b>Deposit amount</b>（定金金额）。 |
| <b>Sample approved</b>（样品已核准） | 采购方核准样品时。 | 仅适用于新产品，返单没有样品环节。 |
| <b>Production done</b>（生产完成） | 供应商完成生产时。 | “完成”指整张订单全部完成，而非第一批。 |
| <b>Proposed ready date</b>（建议就绪日期） | 您知道货物何时能够准备好交接时。 | 这是您认为可信的日期，采购方会核准它。 |

每个日期都要在发生当天记录。一周后才补录，也比完全不记录要好，但在这期间，看板会一直把该阶段显示为延误。

## 采购方记录哪些内容

有些日期，按照设计，您本来就无法自己录入：

- **核准就绪日期。** 采购方核准您提议的日期后，该日期即被锁定，并据此设定后续目标：质检须于当天完成，干净交接须在其后七天内完成。
- **质检通过**与**干净交接**。这两项由采购方确认，通常依据您提供的质检证据与货运代理的收货凭证。
- **合规文件包完整。**

这些正是计算您 <a href="/docs/your-clean-handover-score-zh-hans">交接合格率（CHS）</a> 的依据。一个您自己就能编辑的分数，是没有任何价值的 —— 对您自己也是如此。

## 良好习惯

- **当天就记录。** 当天花五秒钟记录，能省去日后为一个变红的阶段争论的麻烦。
- **提出您真正相信的就绪日期。** 一个能兑现的现实日期，好过一个兑现不了的乐观日期。
- **日期可能延后时，尽早告诉采购方。** 及时商定的新核准日期能让订单保持在正轨上；没人同意就自行延后的日期，会显示为延误。
