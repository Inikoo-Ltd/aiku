# Supply Chain

## Units per pack is set in the SKO composition, read org_stocks.packed_in
HELP-4263 (23 Oct 2026). A supplier product's units_per_pack mirrors the SKO trade unit composition: SupplierProduct::skoPackedIn() is the answer, SyncStockTradeUnits pushes it onto linked supplier products, and AttachOrgSupplierProductToOrgStock copies it when a supplier product is first linked to a stock, and UpdateSupplierProduct overrides any other value except from the Aurora fetchers (the only callers passing skipHistoric: true, which keep Aurora's own value). The edit forms show the field read-only. Read packing from org_stocks.packed_in: stocks.packed_in is null for ~21k Aurora stocks. The supplier product's own trade unit pivot quantity is the size of one supplier unit, not the pack: never sync it to the pack. A carton holds a number of SKOs: when the SKO packing changes, SyncStockTradeUnits passes the old packing and SyncSupplierProductUnitsPerPackFromSko rescales units_per_carton so the SKOs per carton stay the same (the upload stores only units_per_sko × skos_per_carton), but only for supplier products whose pack matched the old packing: ~240 Aurora supplier products carry their own package unit, where the ratio means nothing. Draft PO lines keep the historic supplier product they were added with: the packing PDF reads the live supplier product while the order is in process, and submitting re-points the lines to the current historic.

## A supplier's agent fee overrides the client's, per line
Vika, 13 Nov 2026. suppliers.agent_fee_percentage (set by the agent on its supplier edit page, shown only in the agent's own organisation, or from the Agent Ledger client cards, both through UpdateSupplierAgentFeePercentage) is the fee on that supplier's goods; null falls back to the client's org_agents.agent_fee_percentage, then 2 (SyncAgentInvoiceChargesFromLedger::clientFeePercentage). recordAgentFee groups the invoice lines by stock_delivery_item → supplier_product → supplier and adds up each group's fee, so a container with several suppliers gets one fee line with a mixed note. Any new place that works out an agent fee must use the same per-supplier fallback.

## An order that missed CHO takes the client's CHO penalty off its agent fee
Vika, 13 Nov 2026. When the agent invoice is issued, SyncAgentInvoiceChargesFromLedger::goodsByFeePercentage links each line to its PO through stock_delivery_items.data->purchase_order_transaction_id. The goods of a PO that missed clean hand over pay the fee less org_agents.cho_penalty_percentage, in percentage points: the migration filled 1 for every client and it is the column default for new ones, empty or 0 is no penalty, and the fee never goes below 0%. Only the client sets the penalty, on EditOrgAgent through UpdateOrgAgent; the Agent Ledger card only shows it. GetAgentCleanHandoverScore::cleanHandoverMisses decides a miss and returns null, meaning no penalty, for chs_excluded orders and for orders without approved_ready_at or a hand over date. The PO stage badge and the fee note use the same method. The quarterly CHS commission tiers are separate and display only.
