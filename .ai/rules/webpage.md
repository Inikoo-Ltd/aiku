# Webpage

## Storefront HTML is also cached at the Cloudflare edge
Since 31 Oct 2026 (trial on www.awgifts.eu, every live storefront zone from 15:00 UTC) a Cloudflare cache rule stores anonymous storefront HTML at the edge for 10 minutes, with Tiered Cache (Smart topology) on so one copy near our servers serves every Cloudflare location (bypassed by the iris_vua cookie, X-Inertia, Authorization, static extensions and the Varnish pass paths; X-Aiku-Ssr-Fallback and JSON responses are never stored). In Cloudflare rule expressions `http.request.headers.names[*]` keeps the client's case, so header checks must be `any(lower(http.request.headers.names[*])[*] eq "x-inertia")`: a plain `eq "x-inertia"` let an HTTP/1.1 `X-Inertia` request store Inertia JSON as the page. Every Varnish ban path (BanVarnishWebpage, PurgeVarnishWebpageUrl, PurgeVarnishPath, BreakWebsiteVarnishCache, UpdateWebpageCanonicalUrl, the master price/trade-unit pool bans and varnish:restart) calls `PurgeCloudflareWebsitePages::schedule()`, which books one Cloudflare purge of the website's pages 10 minutes later and lets every other ban in those 10 minutes ride on it (a `Cache::add` lock that lives exactly as long as the delay; ShouldBeUnique would drop bans landing mid-purge). So an edit reaches anonymous visitors within about 10 minutes whatever the edge TTL. The purge is by cache tag, never by host: DetectIrisWebsite sets `Cache-Tag: aiku-website-<id>` on every storefront response (Varnish keeps it, Cloudflare reads and strips it), so purging the tag drops the pages and keeps assets and `/i/` images at the edge. A storefront response that skips the iris middleware group has no tag and is never purged, so keep it out of the edge cache rule. Pages that Varnish refreshes only by TTL, never by a ban (`/reviews` and `/customer-reviews`, 5 minutes in `set_reviews_ttl`), get no purge either, so they must keep a short edge TTL whatever the main rule says. Never purge per ban or per URL: on the Free plan, purging by tag or host is limited to 5 requests a minute per account (bucket of 25), and bans burst to 10k a minute; a 429 releases the job until Cloudflare's Retry-After. A new ban path must call `schedule()` too, or its change stays at the edge for the full edge TTL. A deploy that flushes Varnish (SSR checksum changed) runs `php artisan cloudflare:purge-host` on each production host before the warm-up crawl: the first host purges every website's tag at once under a 2-minute lock, the others skip, and after a 429 the remaining sites are queued 5 a minute; deploys that keep the checksum purge nothing. `php artisan cloudflare:purge-host <slug>` purges one site at once. Any new storefront path that must never be shared between visitors needs adding to that rule's exclusions as well as the VCL pass list. The rules live in `devops/cloudflare/edge-cache-rules.json`; apply or roll back a zone with `devops/cloudflare/edge-cache.sh <zone_id> <host> [--off]`, and change the JSON first, never only the zone. A new storefront zone needs the script run for its storefront host (the canonical host of the website's storefront webpage), or it serves every page from our servers.

## Far scraper countries get their own 24 h edge copy
Since 1 Nov 2026, anonymous storefront requests from US, SG, CN, HK, JP, MX, KR and BR (beacon data: ~1 page per visit, <1% logged in, almost no orders) are rewritten at Cloudflare to add `testa=far` to the query and cached for 24 hours under that separate key, so their copies never reach visitors elsewhere through the shared tiered cache. Varnish strips `testa` before its own lookup and the backend (the `#debug` entry in vcl_init), so Varnish and the app never see it: removing that entry breaks the split. Search engines (Google, Bing, Apple, DuckDuckGo, Yandex, Baidu, Naver, matched by user agent because `cf.client.bot` is not allowed in cache rules on the Free plan) WARP (`ip.src.asnum 13335`, our own offices) and Google's network (`ip.src.asnum 15169`, which also checks ad landing pages with a normal browser user agent) keep the normal 10 minutes. If a Google Ads or Merchant Center review ever sees an outdated page, `php artisan cloudflare:purge <path> --website=<slug>` clears it from the edge at once. Logged-out pages still carry price and stock in the JSON-LD and page data, which is why search engines must stay fresh.
