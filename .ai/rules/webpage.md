# Webpage

## Storefront HTML is also cached at the Cloudflare edge
Since 31 Oct 2026 (trial on www.awgifts.eu, every live storefront zone from 15:00 UTC) a Cloudflare cache rule stores anonymous storefront HTML at the edge (24 hours since 1 Nov 2026, 10 minutes before), with Tiered Cache (Smart topology) on so one copy near our servers serves every Cloudflare location (bypassed by the iris_vua cookie, X-Inertia, Authorization, static extensions and the Varnish pass paths; X-Aiku-Ssr-Fallback and JSON responses are never stored). In Cloudflare rule expressions `http.request.headers.names[*]` keeps the client's case, so header checks must be `any(lower(http.request.headers.names[*])[*] eq "x-inertia")`: a plain `eq "x-inertia"` let an HTTP/1.1 `X-Inertia` request store Inertia JSON as the page. Every Varnish ban path (BanVarnishWebpage, PurgeVarnishWebpageUrl, PurgeVarnishPath, BreakWebsiteVarnishCache, UpdateWebpageCanonicalUrl, the master price/trade-unit pool bans and varnish:restart) calls `PurgeCloudflareWebsitePages::schedule()`, which books one Cloudflare purge of the website's pages 10 minutes later and lets every other ban in those 10 minutes ride on it (a `Cache::add` lock that lives exactly as long as the delay; ShouldBeUnique would drop bans landing mid-purge). So an edit reaches anonymous visitors within about 10 minutes whatever the edge TTL. The purge is by cache tag, never by host: DetectIrisWebsite sets `Cache-Tag: aiku-website-<id>` on every storefront response (Varnish keeps it, Cloudflare reads and strips it), so purging the tag drops the pages and keeps assets and `/i/` images at the edge. A storefront response that skips the iris middleware group has no tag and is never purged, so keep it out of the edge cache rule. Pages that Varnish refreshes only by TTL, never by a ban (`/reviews` and `/customer-reviews`, 5 minutes in `set_reviews_ttl`), get no purge either, so they must keep a short edge TTL whatever the main rule says. Never purge per ban or per URL: on the Free plan, purging by tag or host is limited to 5 requests a minute per account (bucket of 25), and bans burst to 10k a minute; a 429 releases the job until Cloudflare's Retry-After. A new ban path must call `schedule()` too, or its change stays at the edge for the full edge TTL. Breaking a cache by hand (the website and webpage Break cache buttons, the `ban/varnish` links and the `website:break_cache`, `websites:break_cache`, `website:break_iris_cache`, and `varnish:*` commands) calls `purgeNow()` as well, which queues the purge at once instead of in 10 minutes; only those manual entry points (`asController`/`asCommand`) do, while `::run()` callers stay debounced. A deploy that flushes Varnish (SSR checksum changed) runs `php artisan cloudflare:purge-host` on each production host before the warm-up crawl: the first host purges every website's tag at once under a 2-minute lock, the others skip, and after a 429 the remaining sites are queued 5 a minute; deploys that keep the checksum purge nothing. `php artisan cloudflare:purge-host <slug>` purges one site at once. There are two Varnish instances: litio's HAProxy (`haproxy-litio.cfg`, the IP every storefront DNS record points at) uses litio's own Varnish, and boro's uses boro's. Bans reach both through `iris.cache.varnish_hosts`, but `varnish:restart` and `restart_varnish.sh` only ban the Varnish on the host they run on, so a manual full flush must run on both; on 1 Nov 2026 flushing only boro left litio serving untagged pages that no tag purge could clear. Any new storefront path that must never be shared between visitors needs adding to that rule's exclusions as well as the VCL pass list. The rules live in `devops/cloudflare/edge-cache-rules.json`; apply or roll back a zone with `devops/cloudflare/edge-cache.sh <zone_id> <host> [--off]`, and change the JSON first, never only the zone. A new storefront zone needs the script run for its storefront host (the canonical host of the website's storefront webpage), or it serves every page from our servers.

## Only the reviews pages keep 10 minutes at the edge
Since 1 Nov 2026 the main edge rule keeps every anonymous page 24 hours, search engines and Google included, and a second rule after it gives 10 minutes only to `/reviews` and `/customer-reviews`: Varnish refreshes those by TTL (`set_reviews_ttl`), never by a ban, so no purge ever clears them. Search engines need no shorter TTL, because the edge is now exactly as fresh as Varnish: every change that bans a page in Varnish (prices and other page fields, in-stock flips, bulk master prices, webpage edits) purges it at the edge within 10 minutes, and changes that never ban (an exact stock count) were already as stale in Varnish. The 24 h copy for far scraper countries (the `testa=far` rewrite) was removed the same night; Varnish still strips `testa` (the `#debug` entry in vcl_init), harmlessly. If a Google Ads or Merchant Center review ever sees an outdated page, `php artisan cloudflare:purge-host <slug>` clears that website from the edge at once. A path Varnish refreshes only by TTL needs adding to that second rule.
