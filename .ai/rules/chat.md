# Chat

## AI coverage: one outcome per customer message
chat_ai_outcomes holds one row per (session, trigger_message_id), enforced by partial unique indexes; write it only through StoreChatAiOutcome, which keeps the stronger outcome by ChatAiOutcomeEnum case order (draft first). GetChatAiCoverage counts each chat once, by the customer's latest message in the window: the recorded outcome, else a staff reply after it, else is_spam, else is_rubbish (as notice), else not worked. A newer customer message is new work, so an outcome on an earlier one no longer covers the chat. Team windows (today/overnight/team hours) come from config('chat.ai_teams').

## Verified chat facts: two chats to trust, staff removal sticks
Shop facts the CS assistant's reviewers check live in chat_knowledge_entries with source_type verified, written only through RememberVerifiedChatFact (MCP remember_fact). A fact is a candidate until checked while working two different chats, then active for TRUSTED_DAYS; a fact repeating the customer's own words is refused, so one planted message cannot become a rule. Rating a draft wrong_fact disputes the facts in its facts_used; discarding one disputes them only when the agent's next reply says something else (SettleChatAiDraft::settleDiscarded, under REWORDED words kept), because staff discard to clear the box and then type the same answer (INI-400: 230 of 388 discards were followed by a reply within 10 minutes); staff Remove on /chat/ai/verified-facts is final for the tool. HydrateChatKnowledge must never delete verified rows (it only prunes webpage, shop_settings, docs).

## One WhatsApp thread per contact per shop: three lookups stay in step
StoreIncomingWhatsappMessage::findSession, HandleWhatsappCallEvent::resolveSession and StoreMetaChatSession find a contact's thread the same way: withTrashed, never one whose metadata->merged_into is set (MergeMetaChatSessions::MERGED_INTO_KEY), live first, and a binned thread is restored rather than a second one started beside it (that is how prod got its only same-shop duplicates). Each shop writes from its own WhatsApp number and keeps its own customers, so the same phone in two shops is two real conversations: never merge them, they meet in the conversation history (GetCustomerChatHistory::forConversation) instead.

## Draft status stays as staff see it; change_class is the measure
SettleChatAiDraft::statusFor and its thresholds (used/edited/superseded) feed the adoption stats, coverage and the draft-box counts: never retune them to answer a new question. How much staff changed a draft lives in chat_ai_drafts.change_class (MeasureChatAiDraft: as_is, cosmetic, gaps_filled, small, big, rewritten, own_reply, discarded), with words_kept, lag_seconds and open_to_reply_seconds. A draft whose [[gaps]] staff filled counts as "used" in status but gaps_filled here, and only as_is/cosmetic could ever go out without a person. open_to_reply_seconds is time from the message being opened to the reply, not time spent working: never divide payroll by it. chat:measure-drafts runs nightly and is also the backfill.

## Claim outcomes are an estimate by order and timing, one case per chat and order
chat_ai_drafts.claim_check (MeasureChatAiClaim, chat:measure-claims nightly, also the backfill) labels damaged/missing/wrong item drafts by what was done on the order within 7 days: refund invoice, compensation/add_funds_other credit (never pay_return, which every refund-to-balance writes too), replacement delivery note, follow-on in the next order. Values are net in the group currency so bands (config chat.claim_value_bands) compare across shops. Never value a proposal with PlanChatClaim after the fact: once settled it sees nothing left to claim. No order found = no_order, kept out of the rates. GetChatAiClaims counts one case per conversation and order, taking its best-matching draft. Jev's reply verdict is the honesty check, since refunds are not linked to chats.

## Chats handed over by the AI shopping assistant stay out of chat figures
INI-245 (12 Nov 2026): a chat the assistant handed over carries chat_sessions.shopping_assistant_conversation_id. GetChatAiCoverage and the default GetChatReports figures (fromAssistant false) exclude it, because it would read as an unanswered chat overnight and as CS-assistant work; the chat reports page shows only those chats with from_assistant=1, and the AI Assistant report counts hand-overs from shopping_assistant_hand_overs. The assistant transcript is read from the assistant's own tables by GetChatAssistantTranscript and never copied into chat_messages, because GetChatReports counts an ai message as the first reply. These chats stay in the normal inbox, unclaimed queue and alerts (WithUnclaimedChatSessions and AlertUnclaimedChatSessions are untouched on purpose).

## Knowledge notes reach a shop, an organisation or the group
Raul, 14 Nov 2026 (INI-257). A staff note (chat_knowledge_entries, is_manual) reaches one shop (shop_id set), every shop of an organisation (shop_id null, organisation_id set) or the whole group (both null); forShop reads all three.
- Shop notes: anyone who acts on the shop's chat.
- Organisation notes: org admins or group admins only. Group notes: group admins only (UpdateShopChatKnowledgeNote::canManageReach). Editing needs rights on both the old and the new reach.
- A proposed note (waiting for a second yes) cannot be widened.
- rules() is skipped for DELETE and the status route: laravel-actions applies rules() to every route of the action, so asking for title/body there refused every Remove and Use it.

## Shop facts recommend the right shop, rarely: dropshipping by organisation, customers across the UK/EU border
Raul, 17 Nov 2026: recommend another shop only when it truly helps the customer, never as a habit; customers must not be bounced between shops. GetChatShopFacts adds two kinds of shop facts. (1) Dropshipping: every B2B shop links its organisation's dropship shop (DROPSHIPPING_SHOP_BY_ORGANISATION: aw→awd, sk→dssk, es→dse, aroma→awd), which sells almost everything as single units. (2) "Customers in <country>": only across the UK/EU customs border (customsSide, by the organisation's address country, because shops.country_id is wrong for dssk): the shop of the same master_shop that most customers registered in that country bought from over 12 months, with at least HOME_SHOP_MIN_CUSTOMERS and twice this shop's count, only for countries this shop has customers from. Within the EU, or for customers outside both, no fact. Cross-organisation is allowed. The facts say only where customers buy, never that delivery is cheaper or that range, account or prices carry over. AskShoppingAssistant says it at most once, only when delivery, customs, import VAT, dropshipping or a single unit of an outer-only product comes up. Counts are cached a day, read only by the hourly hydration.

## Suggestions taken: one adoption definition, per-person figures for supervisors only
INI-400, 20 Nov 2026. GetChatAiAcceptance is the only definition of CS suggestion adoption: assistant drafts with change_class set (waiting drafts and ones replaced by a newer draft never count); taken = as_is, cosmetic, gaps_filled, small, big; rewritten, own_reply, discarded are not. Bands: high >= 70% (the target for every shop), medium >= 40%, no band under 20 drafts (5 for a week cell). The person is chat_ai_drafts.decided_by_user_id, never chat_messages.sender_id (a chat agent id) or facts.user_id (the routine's account). Per-person figures (IndexChatAiAcceptance users table, the Suggestions list's staff filter and "decided by") are shown only on shops the viewer supervises (chat-m, fulfilment-chat-m, org-admin, or group-admin for all): HR-sensitive. On WhatsApp drafts trigger/reply ids point at meta_chat_messages; never join them to chat_messages.

## Learned rules turn themselves on when strong
INI-402, 20 Nov 2026 (Raul). Staff do not review learned rules (1,302 waited), so LearnChatKnowledge activates a proposed rule by itself at STRONG_CUSTOMERS (5) customers seen within STRONG_SEEN_DAYS (90), strongest first, after IsAboutOneCustomer, IsGeneralAnswer (which refuses case-by-case claim decisions: refund, credit, replacement, compensation) and the contradiction check, which fails closed. A refused rule is asked again only when more customers were told it (evidence.auto_refused_at_customers). An auto-activated rule (evidence.auto_activated) expires STALE_DAYS (180) after staff last said it. Weaker rules stay proposed. Merlin reads active learned rules; CS drafts read the shop's own staff replies (how_staff_answered), with greeting line, emails and references masked.

## Time lost: a right draft retyped, scored by Jev, supervisors only
INI-400, 20 Nov 2026 (Raul: evidence for year-end reviews). chat_ai_drafts.time_lost is set only by ScoreChatSuggestions: an own_reply or discarded assistant draft (not shadow, no [[gap]] left) whose staff reply Jev scored 2+ of 3 (facts.near_match) is true, else false; null = not scored. A discarded draft is scored against the next message after its trigger only when it is the discarding agent's, written after the draft and before the customer wrote again. time_lost_seconds = metadata.writing_seconds of that staff message (useActiveTime in the inbox, chat since 19 Nov, WhatsApp since 20 Nov). chat:score-suggestions must run after chat:measure-drafts (change_class), hence 04:55 UTC. Shown only on shops the viewer supervises (IndexChatAiAcceptance users table, the Suggestions list's Tag filter and chip), never in tickets; both pages answer a raw JSON request with 404, because the unshaped rows carry decided_by and time_lost. The one thing the agent sees of it is Aura's mood (Raul, 20 Nov 2026): her avatar in the draft box is red when that agent has GetChatAiAcceptance::ANGRY_AFTER or more time_lost drafts in the last ANGRY_DAYS (HandleChatAiDraft aura_angry, AuraAvatar angry), with no count and never a colleague's.

## Slack messages kept in aiku: public channels only
Raul, 20 Nov 2026 (HELP-4812, project staff-chat-slack-sync). slack_channels / slack_messages hold Slack as Slack sent it (data = the raw message, unique per channel + ts), separate from staff_messages until Desk channels exist. StoreSlackMessage keeps an event only when channel_type is `channel`; SyncSlackPublicChannels lists `public_channel` only. Private channels, DMs and group DMs are never stored: they arrive only when a person connects their own Slack account, never through the bot. For message_changed the message ts is inside `message`, for message_deleted it is `deleted_ts`; deletions are soft. Joining a channel posts a notice in it, so the sync joins only with --join. Files (INI-417/418): slack_files has one row per Slack file id with its state (pending, copying, copied, external, skipped, not_available, failed) and the copy as media; a job claims the row by moving it to copying (expires after 15 min), never by a cache lock, which is per server; CopySlackMessageFile is dispatched only from StoreSlackMessage::handle (webhook events), never from store(), so history syncs never start bulk downloads; past files go through the paced slack:copy-message-files (--dry-run first). An HTML answer for a non-HTML file is Slack's login page: fail, never store it.

## Slack people directory: one upsert, never overwrite users.slack_user_id
Raul, 20 Nov 2026 (INI-415/416). slack_users holds every Slack person, bots and leavers included (flagged, never deleted), so old messages keep a name. StoreSlackUser is the only writer: slack:sync-users (users.list) and the user_change/team_join webhook events both call it. Match: an aiku user already holding the Slack id wins, else lower(email) when exactly one aiku user has it (any status), else null. users.slack_user_id is filled only when empty and only from a live, non-bot Slack person. StoreSlackMessage takes user_id from slack_users first, then users.slack_user_id, so a re-stored message keeps its author. Emails are never logged.

## Slack channels follow Slack's events; a channel turned private is never stored again
Raul, 20 Nov 2026 (INI-419/420/421). UpdateSlackChannelFromEvent keeps slack_channels current from channel_* and member events (the bot is authorizations.0.user_id of the envelope); member events never create a row, channel_deleted only sets deleted_in_slack_at. A `channel_convert_to_private` message, or any message with channel_type `group` for a known channel, sets is_public false: StoreSlackMessage, the reactions and the sync then skip that channel, and nothing sets it back. joinNewPublicChannel exists but is not called until Raul decides on auto-join. Reactions (slack_message_reactions) are stored only on held messages of public channels, never fetched; history reactions are added from slack_messages.data and never removed by it, since an event may be newer. slack:sync-public-channels --history runs nightly at 02:40 UTC under logSchedule + sentryMonitor (the failure warning) and writes slack_sync_runs.

## Who may see a Slack channel: one scope, SlackChannel::visibleTo
Raul, 21 Nov 2026 (INI-428). SlackChannel::scopeVisibleTo(User) and isVisibleTo(User), which uses the scope, are the only answer to "may this aiku user see this Slack channel". Every screen, search, file download, websocket and API asks them; never check is_public/is_ignored by hand. Kept = is_public, not is_ignored, not deleted_in_slack_at (scopeKept); anything else is visible to no one, so phase 4 (private) must extend the scope, which fails closed. Eligibility lives in SlackChannel::userMayReadPublicChannels: an active aiku user, not staff who only work for agents (User::worksOnlyForAgents), linked to an active non-bot Slack person (slack_users.user_id). Membership is not required for public channels. To open public channels to all staff, delete its SlackUser line. slack_channel_members (anyone in the channel, the bot included) is filled by slack:sync-channel-members and kept current by UpdateSlackChannelMember from member_joined_channel/member_left_channel, kept channels only. It is for display, private channels and unread counts, not for access to public channels.

## Slack edits, custom emoji, pins and bookmarks: what is kept and when
Raul, 21 Nov 2026 (INI-422/424/425). StoreSlackMessage::store() writes a slack_message_versions row (the old text + data) only when the text differs, inside the same transaction; unfurls, reply counts and history re-reads never make one. slack_emojis: one row per custom emoji, aliases keep alias_for and no image, removed ones get removed_in_slack_at and keep their image, a rename keeps the row; images only from https *.slack-edge.com / *.slack.com, without the bot token. ResolveSlackEmoji turns a name (skin tones included) into Unicode or our copy; its STANDARD map covers common Slack names only. Pins are pinned_at/pinned_by_slack_user_id on kept messages of public, non-ignored channels (a file pin marks the message it was first shared in; anything else is skipped, never fetched). Slack has no bookmark events: slack:sync-pins-and-bookmarks re-reads them nightly. New Slack calls go in their own commands, never in slack:sync-public-channels, so a missing scope cannot stop the message catch-up.

## Every nightly Slack command records its run and is listed on the sync health page
Raul, 21 Nov 2026 (INI-426). slack_sync_runs has one row per run of every nightly Slack command, named in `command`. A new nightly Slack command wraps its asCommand in SlackSyncRun::record($this->commandSignature, fn () => $this->handle()) (a `failed` list in its totals becomes the run's error) and is added to ShowSlackSyncHealth::NIGHTLY_COMMANDS, or /devops/slack-sync never shows it nor warns when it fails, stops halfway or does not run. That page is for engineers only (Ticket::canBeManagedBy + hasGroupAccess). Its per-channel message counts and the reaction count are cached 10 minutes (STATS_CACHE_KEY); everything a warning reads stays live. The quiet warning counts Mon-Fri 07:00-16:00 UTC minutes since the newest message (QUIET_WORKING_MINUTES).

## Slack mention notifications: live events only, once per person and message
Raul, 21 Nov 2026 (INI-445). NotifySlackMentions runs only from StoreSlackMessage::handle (webhook), never from store(), so history syncs never notify. A new message notifies when this store created it; an edit only people its replaced wording (latest slack_message_versions row) did not mention, so a typo fix on a backfilled message pings no one. The notification id is a UUID v5 of message id + user id: an existing row means already told. Only <@U…> mentions, subtypes in NotifySlackMentions::SUBTYPES, never the author, only SlackChannel::isVisibleTo. UserNotificationEnum::SLACK_MENTION defaults to [] and [] means nothing at all, not even the bell. A mention inside a thread reply notifies like any other (the link opens the thread at the reply); being told about replies in a thread you started or took part in is not built, nor <!here>, <!channel> or user groups. A mention reaches only an aiku user linked to that Slack person by slack_users.user_id under the access policy's rule (live, non-bot, not restricted, same email); users.slack_user_id is typed by the person and never used. The Slack direct message escapes &, < and > (escapeForSlack).

## Slack live events: one group channel, webhook only; read positions are aiku's own
Raul, 21 Nov 2026 (INI-440/443). SlackChannelMessageChanged is dispatched only from StoreSlackMessage::handle() and StoreSlackMessageReaction::handle(), never from store() or fromStoredMessage(), so history syncs broadcast nothing. It goes on one private channel per group, grp.slack.{group} (auth: same group + SlackChannel::visibleTo($user)->exists()), and broadcastWhen() re-checks kept(). A Slack channel visible to only some people (phase 4) must never go out on grp.slack.{group}: give it its own broadcast channel. slack_channel_reads holds each person's read position, independent of Slack; it only moves forward (greatest), a channel seen for the first time starts read (MarkSlackChannelRead::upToNow onlyMissing), and GetSlackChannelUnreadCounts counts only visibleTo channel ids, main stream only (thread replies left out unless thread_broadcast), capped at 100.
